Intent: Make all my projects learn from each other, so that what any project learns becomes a foundation every project builds on, instead of being reinvented.

Main effort: Knowledge must travel with its context. A technique that arrives without the situation it was developed in gets applied blindly, which is worse than not having it. Where reach and context conflict, context wins.

Measures:

Whatever a project adds to its innovations/ reaches all the other projects the next time they are opened.
A project being opened gets the best current know-how from all other projects.
A new project starts with the best current know-how of all projects, not a copy of the last one I worked on.
Each project keeps the knowledge that fits its own work; what it doesn’t take is never lost and stays available to others.
The same knowledge, developed slightly differently in different projects, is recognised as the same and doesn’t spread as duplicates.
Every project holds the same standard for what can be added, including the context it was developed in.
Agents load only what’s relevant to their current task, even when the knowledge is ten times larger.
After losing a computer or any other irrecoverable problem, the full capability is back by cloning the project, empty and working, ready for projects to start generating knowledge again.

Context:

Every project has an innovations/ folder where it adds whatever it produced that’s usable by other projects, with the context it was developed in.
All these folders descend from one original folder, copied forward from project to project. Each is a snapshot of that line at the moment it was copied, plus whatever the project added afterwards. The standard for what can be added evolved along the same line, so older copies have a looser one.
New projects get a copy of whichever project I worked on last, so useful knowledge from other projects is missed, and the same technique gets reinvented slightly differently in different places.
The same idea is often written differently in different projects; similar names can mean different things.
Projects can sit unopened for weeks.
The capability is what’s valuable. The knowledge can be regenerated or taken from industry standards; the capability to manage ever-growing know-how is not small to build, so it must survive anything.
