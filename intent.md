Context

Every project has an innovations/ folder where it adds whatever it produced that’s usable by other projects, with the context it was developed in.
All these folders descend from one original folder, copied forward from project to project. Each is a snapshot of that line at the moment it was copied, plus whatever the project added afterwards. The standard for what can be added evolved along the same line, so older copies have a looser one.
New projects get a copy of whichever project I worked on last, so useful knowledge from other projects is missed, and the same technique gets reinvented slightly differently in different places.
Today I copy innovations/ from an existing project into a new one; I don’t want new projects to depend on that.
The same idea is often written differently in different projects; similar names can mean different things.
Projects can sit unopened for weeks.
The capability is what’s valuable. The knowledge can be regenerated or taken from industry standards; the capability to manage ever-growing know-how is not small to build, so it must survive anything.
My projects are developed on my Linux Raspberry Pi, where every project is in /home/mr/Desktop/python. (Added 2026-10-24 on the CEO’s go, with the two lines under Boundaries.) When I am away from the Pi, I clone my projects and this capability from GitHub and continue elsewhere. Anyone can clone this capability and have it working, on Linux or Windows, given an agent and Python, which my projects use anyway. The know-how itself I bring from my projects and other places; the capability does not need to carry it between machines.
How a project’s agents learn what is available to them on the computer, this capability included, is my arrangement: for example, a file I add to every project listing it. This capability provides what such an arrangement needs in order to point agents to it.

Higher intent

One level up: My projects are quick to set up and my time goes to their work, not to how to do simple things. What one project learns is not lost when I forget it, and it is available to other projects with the context it was developed in, so applying it is predictable. How agents direct and act coherently within a project is the method’s, from directed_opportunism.

Two levels up: get my many project ideas finished, both those that depend on others and those that stand alone, by directing them only through sharp intent, and refine and grow the innovations I come up with while doing them.

Intent

Make all my projects learn from each other, so that what any project learns becomes a foundation every project builds on, instead of being reinvented.

Main effort

Knowledge must travel with its context. A technique that arrives without the situation it was developed in gets applied blindly, which is worse than not having it. Where reach and context conflict, context wins.

Measures

M1. What any project learns, with the context it was developed in, becomes available to every other project, whether or not the project it came from is being worked on.

M2. Time a project spends unused does not cut it off: when work on it resumes, it can get what was learned meanwhile.

M3. A new project can draw on the best current know-how of all projects, not only on the last project I worked on.

M4. A project takes only what fits its own work; nothing any project contributes is lost, and what a project does not take stays available to the others.

M5. The same knowledge, developed slightly differently in different projects, is recognised as the same and doesn’t spread as duplicates.

M6. Every project holds the same standard for what can be added, including the context it was developed in, and what it adds meets that standard.

M7. Agents load only what’s relevant to their current task, even when the knowledge is ten times larger.

M8. After losing a computer or any other irrecoverable problem, the full capability is back by cloning the project, empty and working, ready for projects to start generating knowledge again.

M9. I can keep any contribution from being available to a project, or to every project, when I know it would mislead or use resources I don’t want used; a project’s executive can decline what does not fit its project’s work.

M10. The capability saves more of my resources (my time and attention, and the tokens and time of agents) than it and the agents using it consume.
